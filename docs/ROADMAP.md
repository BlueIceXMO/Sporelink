## 0. 定位声明与文件范围

本文件先划清两个定位，再描述功能基线。除本节明确标注为 Explore 的内容外，全文不借用任何外部产品的主张。

### 0.1 Explore 的答案（外部说明，不是 Sporelink 的定位）

以下是 **Explore 的答案**，不是 Sporelink 的答案。原文列出，仅用于划清边界：

- **对话即结构**：每条回答都可以成为新卡片，卡片组成树，树可以并排比较。
- **上下文可解释**：发送前能看到模型到底收到了哪些消息、文档、引用和知识。
- **知识可积累**：把理解写成原子知识，带来源、置信度和关联；之后的回答可以引用它。
- **数据属于用户**：本地 Vault、明文导出、无强制账号、无遥测、模型 Key 由用户自己持有。
- **AI 可替换**：OpenAI、Claude、DeepSeek、Gemini、OpenRouter、本地模型共用一套网关。

> 这些是 Explore 的定位，不是 Sporelink 的定位；不沿用其措辞、价值排序或产品承诺。

### 0.4 本版假设的使用场景

以下不是最终定位，只是 v0.1 需要覆盖的使用场景，后续可修正：

- 研究者 / 学生：读论文、梳理概念、建立文献网络。
- 工程师：拆解系统、比较方案、保留决策依据。
- 写作者 / 分析师：从一个问题发散出结构，再收敛成稿。
- 长期知识工作者：希望聊天记录变成可检索的资产，而不是沉底日志。

### 0.5 v0.1 工程约束

这些是交付约束，不是产品定位：

1. 数据保存在本地，可完整导出/导入。
2. 无遥测、无广告、无远程配置。
3. 模型 Key 由用户持有，存 OS keychain；渲染进程不可见。
4. 模型供应商可替换，不绑定单一 API。
5. 无模型配置时仍可整理、阅读、搜索、导出；模型调用按用户配置执行。
6. 核心操作可键盘完成，界面支持减少动效与窄屏。

## 1. 核心概念

| 对象 | 定义 |
| --- | --- |
| **Vault** | 一个本地知识库根目录，包含多个 Project、全局知识、设置与附件。 |
| **Project** | 一次持续的探索，拥有卡片图、文档、知识与导出边界。 |
| **Card** | 一个可独立阅读/对话的思考单元；有类型、标题、位置、父子关系。 |
| **Turn** | 卡片内的一轮“用户输入 + AI 回答”，可折叠、可引用、可分支。 |
| **Message** | Turn 内的单条消息，含角色、内容、推理、引用、工具结果、状态。 |
| **Edge** | 卡片关系：父子、平行、分支、引用、合并。 |
| **Context** | 发送给模型的实际输入：路径消息、置顶、文档片段、知识、工具结果。 |
| **Document** | 导入的本地材料，解析为可引用的 Chunk。 |
| **Knowledge** | 原子化理解/判断，带来源、类别、置信度、关联。 |
| **Collection** | 收藏、专题、保存的视图或导出集合。 |
| **Model Profile** | 一家供应商 + Key + 模型 + 能力/成本参数的组合。 |
| **Run** | 一次可追踪的 AI 执行：输入、工具、模型、token、耗时、结果。 |

### 卡片类型

- **Root**：项目起点。
- **Dive（深潜）**：从某条回答/选中文本向下追问，继承路径上下文。
- **Diverge（发散）**：与来源卡片平行，探索相邻方向。
- **Branch（分支）**：从上游某个分支点分出，继承该点之前的对话。
- **Merge（合并，P1）**：把多条分支的结论收敛成一张综合卡。
- **Note（笔记，P1）**：不依赖对话的纯 Markdown/知识卡。

## 2. 关键用户旅程

### 2.1 从问题到卡片树

1. 新建项目，写下问题。
2. AI 流式回答；可展开推理、查看引用、停止/重试。
3. 选中一段回答 → 深潜；或从回答创建发散卡；或在某一轮设置分支点。
4. 画布上同时看到多条路径；并排比较两个回答。
5. 把关键结论收藏为知识；导出项目或生成摘要。

### 2.2 从材料到理解

1. 导入 PDF/DOCX/Markdown。
2. 阅读窗与卡片并排；选中段落 → 提问/引用/生成卡片。
3. 本地模型翻译、格式化、术语标注。
4. 把理解写成知识条目，挂回原文位置。
5. 以后提问时，知识作为“锚点”被检索并引用。

### 2.3 从积累到复用

1. 全局搜索“某个概念在哪里出现过”。
2. 打开知识花园，查看相关卡片、文档、结论。
3. 把旧知识加入新项目的上下文。
4. 导出 Markdown/HTML/PDF，或生成可分享的静态阅读页。

## 3. 功能地图

优先级：**P0 = v0.1 必须**；P1 = v0.1 后段 / 0.1.x；P2 = 后续。

### 3.1 Vault 与工作区

- **P0 多 Vault**：每个 Vault 独立数据库/附件/设置；可切换、重命名、迁移。
- **P0 项目**：新建、重命名、描述、封面色、归档、复制、删除、恢复、最近打开。
- **P0 文件夹/标签**：项目分组；标签可跨项目筛选。
- **P0 自动保存 + 快照**：定时快照、手动快照、崩溃恢复、版本回滚。
- **P0 本地 profile**：昵称、头像、语言、默认模型；无密码、无账号。
- **P0 多窗口/标签页**：同一 Vault 打开多个项目；窗口状态恢复。
- **P1 模板**：研究、阅读、决策、写作、空白卡片树。
- **P1 项目级设置**：默认模型、上下文预算、只读锁定、自动摘要开关。
- **P1 导入向导**：Markdown 文件夹、JSON、HTML、旧版数据。
- **P2 项目依赖/引用**：项目之间共享知识条目与文档。

### 3.2 卡片画布与图

- **P0 画布**：缩放、平移、适配、聚焦、迷你地图、当前卡高亮。
- **P0 自动布局 + 手动位置**：自动排列不重叠；手动拖动后保持。
- **P0 视图模式**：卡片画布、树状大纲、列表；同一数据不同视图。
- **P0 卡片操作**：新建、重命名、复制、删除、归档、收藏、锁定、导出。
- **P0 关系**：父子、平行、分支、引用；连线可读。
- **P0 面包屑 + 键盘导航**：上一张/下一张、回到根、跳转兄弟卡。
- **P0 多选与并排比较**：选中两张卡，左右对照；差异高亮。
- **P1 2.5D/3D 视图**：深度、层级、空间记忆；2D 降级。
- **P1 合并卡**：选择多条路径 → 生成综合卡；保留来源边。
- **P1 卡片内分栏**：同卡左右对照两个回答/两个模型。
- **P1 画布批注**：卡片间箭头、分组框、文字标签。
- **P2 自由白板**：卡片、图片、文档、网页剪藏混合布局。
- **P2 图查询**：按关系/标签/时间筛选子图。

### 3.3 对话、轮次与消息

- **P0 流式输出**：首 token 尽快显示；可停止；失败可重试。
- **P0 推理过程**：折叠/展开；与最终回答分离。
- **P0 Markdown**：标题、列表、表格、引用、代码、脚注、链接。
- **P0 数学与代码**：KaTeX/MathJax；代码高亮、复制、语言标识。
- **P0 引用**：回答中的来源角标；点击跳到消息/文档/知识。
- **P0 编辑**：用户消息编辑后重发；AI 消息可编辑整理；编辑保留历史版本。
- **P0 删除**：删除单条/单轮/整卡；回收站与恢复。
- **P0 引用与选中工具**：引用、深潜选中、开新线索、复制、搜索。
- **P0 轮次折叠**：长对话折叠为轮次条；展开定位。
- **P0 重新生成**：同模型重试、换模型重试、保留旧版本对比。
- **P0 上下文预览**：发送前查看 system、路径消息、引用、文档、知识、工具结果。
- **P0 token/成本预估**：按模型上下文窗口计算；超限提示与裁剪策略。
- **P0 附件**：图片、文本、文档；本地存储；视觉模型能力检查。
- **P1 多候选回答**：同一轮生成 2–4 个候选，择优保留。
- **P1 回答对比**：两个模型/两个提示词的并排 diff。
- **P1 语音输入/朗读**：本地 STT/TTS（可选）。
- **P2 实时协作光标/评论**：见 §3.11。

### 3.4 上下文编译器（核心差异点）

发送给模型的内容不应是“整段聊天记录”，而应是一个可解释的编译结果。

- **P0 来源**：当前路径消息、置顶消息、引用片段、文档 Chunk、知识条目、工具结果、系统提示。
- **P0 优先级**：用户置顶 > 最近轮次 > 引用 > 检索知识 > 文档；可手动调序。
- **P0 预算**：按 token 计算；保留最后一条用户消息；超出时按策略裁剪并显示“丢了什么”。
- **P0 去重**：同一文档片段/知识只出现一次；相似内容合并。
- **P0 预览**：逐条显示来源、token、为什么被包含；可临时禁用。
- **P0 可复现**：保存本次 Context 快照，回答可追溯到当时的输入。
- **P1 自动摘要**：对超长历史做分层摘要；摘要可编辑。
- **P1 来源权重**：用户给某条知识/文档更高权重。
- **P2 智能编译**：根据问题类型自动选择路径/检索策略，并解释理由。

### 3.5 文档与阅读

- **P0 格式**：PDF、DOCX、PPTX、HTML、TXT、Markdown、常见代码/JSON。
- **P0 本地解析**：页码、段落、标题层级、表格文本；失败定位到页/格式。
- **P0 阅读窗**：与卡片并排；目录、进度、缩放、搜索。
- **P0 引用**：选中段落 → 引用/提问/生成卡片；引用带页码。
- **P0 文档卡片**：为一份文档创建专属卡片；章节卡片。
- **P0 附件管理**：导入、重命名、删除、去重、存储位置。
- **P1 OCR**：扫描 PDF/图片；语言包可选安装。
- **P1 翻译/格式化**：本地或用户选择的模型；长文分批、可取消。
- **P1 术语表**：自动提取术语 + 解释 + 原文位置。
- **P1 多文档对比**：同主题文档并排，差异/共识。
- **P2 表格/公式/图表提取**：结构化输出到卡片。
- **P2 文献库导入**：Zotero/BibTeX/EndNote 元数据。

### 3.6 知识花园与记忆

- **P0 知识条目**：标题、正文、类别、来源、置信度、标签、时间。
- **P0 来源链**：每条知识挂到消息/文档 Chunk/卡片；可反查。
- **P0 理解工作流**：用户用自己的话解释 → 模型指出偏差 → 修改 → 入库。
- **P0 检索**：关键词 + 可选向量；回答时引用知识并标注来源。
- **P0 知识图谱**：节点、边、缩放、筛选、聚焦；按项目/全局切换。
- **P0 项目摘要**：按卡片树结构生成；可编辑、可导出。
- **P1 复习队列**：间隔重复；每周回顾待巩固知识。
- **P1 冲突检测**：相似知识/相反结论提示；人工裁决。
- **P1 知识合并/拆分**：合并重复条目；拆分复合结论。
- **P2 跨 Vault 知识网络**：共享知识包；导入/导出。
- **P2 自动知识抽取**：从回答中建议原子知识，用户确认后入库。

### 3.7 搜索与命令

- **P0 全文搜索**：项目、卡片、消息、文档、知识；结果高亮与跳转。
- **P0 过滤**：项目、时间、角色、卡片类型、标签、收藏。
- **P0 命令面板**：新建、切换项目、搜索、打开设置、运行工具。
- **P0 对话内搜索**：当前卡片内查找并跳转。
- **P1 语义搜索**：本地 embedding；无模型时退回 FTS。
- **P1 保存搜索/智能集合**：按查询动态更新。
- **P1 图查询**：按关系、深度、标签筛选卡片。
- **P2 自然语言查询**：本地模型转结构化查询，结果可解释。

### 3.8 收藏、集合与导出

- **P0 收藏**：消息、轮次、卡片、项目、知识。
- **P0 集合**：手动集合 + 智能集合（按标签/时间/搜索）。
- **P0 导出**：项目 JSON、全量备份、Markdown、单文件 HTML、PDF。
- **P0 选择性导出**：只导出收藏轮次/选中卡片/某个分支。
- **P0 导入**：Sporelink JSON、Markdown 文件夹、HTML；冲突时重新分配 ID。
- **P1 静态阅读页**：带主题、目录、引用、可分享 HTML。
- **P1 导出模板**：文章、提纲、研究笔记、Anki/CSV。
- **P2 发布/分享**：只读链接或本地静态站点（用户自托管）。

### 3.9 模型运行时与 AI 能力

- **P0 Provider**：OpenAI、Anthropic、DeepSeek、Google Gemini、OpenRouter、任意 OpenAI-compatible、本地（llama.cpp/Ollama/LM Studio/vLLM）。
- **P0 连接管理**：Key、Base URL、默认模型、能力、测试、模型列表；Key 存 OS keychain。
- **P0 模型角色**：对话、推理/强模型、功能模型（标题/摘要/标注）、embedding、rerank。
- **P0 流式与取消**：统一事件；超时、429/5xx 退避；错误可读。
- **P0 能力检查**：上下文窗口、视觉、工具、JSON/结构化输出；不足时明确报错。
- **P0 成本/用量**：本地记录 token、耗时、估算费用；按项目/模型统计。
- **P0 无静默回退**：切换 provider 必须用户确认；不把内容发给未选择的供应商。
- **P0 Mock 模型**：离线占位；可编辑回复；用于 UI/流程测试。
- **P1 路由策略**：按任务/成本/延迟选择模型；规则可见、可覆盖。
- **P1 结构化输出**：JSON Schema、引用、表格；失败重试。
- **P1 Prompt 库**：项目级/全局模板；变量；版本。
- **P2 多模态**：音频转写、图像理解、视频章节（按模型能力）。
- **P2 模型评测**：同一问题跑多模型，记录质量/成本/延迟。

### 3.10 工具、代理与自动化

- **P0 工具**：查询历史、查询知识、读取文档片段、计算器；调用与结果显示在消息中。
- **P0 运行轨迹**：每次工具调用有输入/输出/耗时/错误；可展开。
- **P0 审批**：有副作用的工具（写文件、联网）必须逐步确认。
- **P1 代码沙箱**：本地受限执行；只读/临时目录；资源限制。
- **P1 工作流**：多步任务（检索 → 阅读 → 总结 → 建卡），可见计划与预算。
- **P1 批处理**：对多张卡执行摘要/标注/翻译；队列与取消。
- **P2 定时任务**：每日回顾、周报、监控主题更新。
- **P2 插件 API**：只读工具优先；权限清单；沙箱。
- **P2 MCP/CLI**：外部工具接入；显式授权。
- **P2 网页剪藏**：浏览器扩展保存选中内容/整页到 Vault。

### 3.11 同步、协作与多设备（后续）

- **P2 加密同步**：用户自带 WebDAV/S3/Git；端到端加密；无中心账号。
- **P2 CRDT**：离线编辑合并；按卡片/消息粒度冲突提示。
- **P2 共享 Vault**：只读分享、评论、建议；权限模型。
- **P2 移动端**：快速捕获、阅读、卡片浏览；离线缓存。
- **P2 多用户**：团队 Vault、角色、审计日志（本地/自托管）。

### 3.12 设置、主题、语言与无障碍

- **P0 模型设置**：连接、角色、默认值、Key、测试、删除。
- **P0 外观**：主题 token、字号、密度、卡片宽度、动效减弱。
- **P0 主题**：9 套原创主题（Ink、Moss、Ember、Sakura、Midnight、Sand、Violet、Ocean、Amber），即时预览。
- **P0 语言**：中 / 繁 / 英；日期/数字格式。
- **P0 快捷键**：发送、换行、搜索、新建、切卡、停止、命令面板。
- **P0 隐私**：本地模式说明、清除数据、导出脱敏、网络目标提示。
- **P0 数据**：备份、恢复、迁移、附件位置、缓存清理。
- **P0 编辑权限**：项目只读、卡片锁定、导出只读快照。
- **P1 无障碍**：键盘全导航、ARIA、焦点环、对比度、屏幕阅读器。
- **P1 响应式**：窄屏/平板布局；触控手势。
- **P2 自定义主题**：token 编辑器、导入/导出主题包。

### 3.13 引导与帮助

- **P0 首次启动**：语言 → 主题 → 模型（可跳过）→ 欢迎页。

## 4. 数据模型

### 4.1 实体

```text
Vault
 ├─ Project
 │   ├─ Card (graph)
 │   │   ├─ Turn
 │   │   │   └─ Message
 │   │   ├─ Edge
 │   │   └─ ContextSnapshot
 │   ├─ Document → Chunk → Citation
 │   ├─ Knowledge → SourceRef
 │   ├─ Collection
 │   └─ Run
 ├─ Document (global)
 ├─ Knowledge (global)
 └─ Settings / ModelProfile / Attachment
```

### 4.2 关键字段

- **Card**：`id, projectId, kind, title, parentId?, branchPointMessageId?, position, locked, createdAt, updatedAt`。
- **Turn**：`id, cardId, index, collapsed, modelProfileId, contextSnapshotId`。
- **Message**：`id, turnId, role, content, reasoning, citations[], attachments[], status, editedFrom?, createdAt`。
- **Edge**：`id, fromCardId, toCardId, kind(parent|sibling|branch|reference|merge), metadata`。
- **ContextSnapshot**：`id, cardId, turnId, items[{sourceType, sourceId, tokens, reason}], totalTokens, createdAt`。
- **Knowledge**：`id, title, body, category, confidence, sourceRefs[], tags[], embedding?`。
- **Document/Chunk**：`id, path, mime, hash, pages, chunks[{id, page, text, offsets}]`。
- **Run**：`id, provider, model, purpose, inputTokens, outputTokens, cost, latency, toolCalls[], error?`。

### 4.3 不变量

- 每个 Project 至少一个 Root；孤立卡片导入后成为新 Root。
- Branch 必须指向合法的分支点；Branch 的上下文 = 上游路径到分支点。
- Merge 至少有两个来源边；删除来源不删除综合卡。
- 删除卡片时子卡重新挂接或标记孤立，不静默丢数据。
- 任何导出不包含 Key；ContextSnapshot 可复现。
- 所有写操作有事务与 revision；崩溃后可恢复。

## 5. 技术架构

### 5.1 形态

桌面应用优先（Windows/macOS/Linux），本地数据库，本地文件，本地模型可选；未来可加移动端/CLI。

M0 用 ADR 决定 shell：

- **推荐 Electron + TypeScript + React + SQLite**：文档、模型、3D 生态成熟，交付风险低。
- **备选 Tauri 2 + Rust core + React/TS**：体积小、权限强，但集成成本高。
- 领域层独立，shell 可替换；不双线开发。

### 5.2 分层

```text
apps/desktop        窗口、菜单、IPC、更新（默认关闭）
packages/domain     卡片图、轮次、上下文、知识、集合的不变量
packages/storage    SQLite schema、迁移、FTS、附件、快照
packages/ai         provider 适配器、tokenizer、路由、工具、运行记录
packages/documents  parser、OCR、chunk、citation
packages/search     FTS + 向量 + 图查询
packages/ui         React 组件、设计 token、主题、i18n
packages/contracts  IPC、导出 schema、版本化 JSON
```

### 5.3 存储

- SQLite（WAL）+ FTS5；附件内容寻址；embedding 可存 BLOB/扩展。
- 项目级 revision；写入事务化；导出稳定 JSON。
- 事件日志用于撤销、快照与未来 CRDT；迁移单向升级。
- 加密：可选 SQLCipher 或 OS 级磁盘加密；Key 单独存 keychain。

### 5.4 模型网关

- 统一接口：`streamChat / complete / embed / rerank / listModels / test`。
- 适配器：OpenAI Chat/Responses、Anthropic Messages、Gemini、OpenAI-compatible、本地运行时。
- 统一事件：`delta / reasoning / tool-call / tool-result / usage / error / done`。
- 能力注册表 + 参数裁剪；不静默降级。
- 直连供应商；不经过 Sporelink 中转；Key 不进 renderer。
- 超时/取消/退避；不跨 provider 自动回退。

### 5.5 文档与索引

- 解析在 worker 执行；按页/块流式返回；失败定位。
- OCR 可选；语言包按需安装。
- FTS 先建，向量后建；索引可重建；不阻塞 UI。

### 5.6 界面

- 三栏：左侧 Vault/导航，中间画布/卡片，右侧图/大纲。
- 底部胶囊输入：模型、附件、发送/停止、上下文入口。
- 卡片悬浮材质、层次阴影、微光；主题 token 驱动。
- 设置：左侧分组 + 右侧内容；即时预览。
- 动效克制；支持 reduced-motion；2D 降级。

### 5.7 安全与隐私

- Renderer 沙箱、contextIsolation、类型化 IPC；不直接读文件/Key。
- Key 只进 OS keychain；日志脱敏；导出不含 Key。
- 网络：仅用户配置的 provider 域名；主机白名单；请求前展示目标。
- 无遥测、无广告、无远程配置；更新检查默认关闭。
- 依赖审计、签名构建、可复现打包。
- 代码签名首选 SignPath Foundation（免费 OSS）；安装包/签名流程见 `release.md`。

### 5.8 性能预算

- 冷启动 < 2s（不含模型加载）。
- 1,000 卡 / 20,000 消息可打开、可搜索。
- FTS 首屏 < 100ms；画布拖拽 ≥ 30fps。
- 流式首 token 尽快显示；取消 < 200ms。

## 7. 验收

### 7.1 场景验收

- **研究**：导入论文 → 阅读 → 生成 3 层卡片 → 知识入库 → 导出。
- **决策**：同一问题开 3 条分支 → 并排比较 → 合并结论。
- **长期使用**：关闭重开 → 数据完整 → 搜索命中 → 上下文可复现。
- **模型切换**：同一卡片换 provider → 明确提示 → 运行记录可查。
- **断网**：本地模型/Mock 可用；无 provider 配置时不发请求。

### 7.2 数据验收

- 导出 → 清空 → 导入：卡片图、消息、引用、知识、收藏、文档引用完整还原。
- 崩溃恢复到最后一次成功事务；导入失败不破坏现有数据。
- 删除有回收站；快照可回滚。

### 7.3 安全验收

- Key 只在 keychain；renderer/日志/导出不可见。
- 抓包：无遥测/广告/远程配置；只访问已配置 provider。
- 自定义 Base URL 有明确警告；TLS 校验不可关闭。

### 7.4 体验验收

- 首次 5 分钟内完成：建项目 → 提问 → 深潜 → 收藏 → 导出。
- 所有核心操作可键盘完成；窄屏可用。
- 主题切换无闪烁；减少动效生效。

## 10. 候选超集方向（下一步讨论）

这些不是 v0.1 承诺，而是用于讨论“比现有产品更丰富、更有效”的增量：

- **多父图 / 合并卡**：一张卡可由多条分支共同支撑；结论可追溯。
- **分支实验**：同一问题批量跑多模型/多提示词，按质量/成本/延迟对比。
- **研究代理**：计划 → 检索 → 阅读 → 记笔记 → 建卡，全程可见、可中断、可回放。
- **知识复习**：间隔重复、主动回忆、概念测验。
- **矛盾检测**：同一主题下相反结论自动提示，要求补证据。
- **引用网络**：文档、消息、知识之间的双向引用图。
- **项目间知识复用**：跨 Vault 的知识包与依赖。
- **模板市场/本地脚本**：用户自定义工作流，不依赖云。
- **本地语义索引**：增量 embedding、模型可替换、索引可重建。
- **协作与分享**：只读发布、评论、建议、团队 Vault。
- **多模态工作台**：音频、视频章节、白板、图片标注。
- **可观测性**：每次回答的上下文、工具、成本、延迟、质量评分。
- **可验证性**：回答附带证据链、置信度、可复现 Run。
