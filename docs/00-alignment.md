# 00 · 技术栈切换对齐说明

## 1. 目的

把 Explore 现有的交互与功能，迁到新的技术栈上。

本文件只定义**对齐边界、层间职责与验收方式**，不定义产品哲学，不写宣言，不替用户规定学习路径。

对齐原则：

- 交互语义保持：树状 cell、线性溯源、轮次展开、卡片操作、设置与主题。
- 实现全部替换：桌面壳、IPC、存储、模型网关、构建链。
- 不新增 Explore 没有的功能；不因为换栈而删掉 Explore 已有功能。

## 2. 固定技术栈

| 层 | 选型 |
| --- | --- |
| 桌面壳 | Tauri 2 |
| 系统语言 | Rust |
| UI 语言 | TypeScript |
| UI 框架 | React |
| 构建 | Vite |
| 业务存储 | VelesDB（`velesdb-core`） |
| 密钥 | OS keychain |
| 版本管理 | Git |
| 审查 | VS Code |
| 主开发 | DSH |

运行形态：

- 仅桌面：Windows / macOS / Linux。
- 不做浏览器版，不做本地 HTTP 服务，不嵌入 Node 运行时。
- WebView 不直接访问网络、文件系统或密钥。
- VelesDB 是唯一业务数据存储；密钥不进 VelesDB。

## 3. 对齐基准

### 3.1 结构

- Explore 的 `card` 对应 Sporelink 的 `cell`。
- `cell` 是最小单元，内含轮次与消息。
- `cell` 之间只有父子关系：根、深潜、分叉、重答。
- 上下文按线性溯源：从当前 cell 上溯到根，按路径拼接消息。
- v0.1 不做跨 cell 连线，不做图搜索深度，不做图结构特性。

### 3.2 功能分类

| 类别 | 内容 | v0.1 |
| --- | --- | --- |
| A. 本地可复刻 | cell/轮次、树状导航、3D 卡片树、主题、设置、模型选择、BYOK、搜索、收藏、导入、示例项目入口、快捷键、消息编辑/删除/重答/引用 | 全做 |
| B. 本地替代 | Explore 已有的总结、知识条目、文档阅读/解析、历史检索入口；按原交互对齐，不新增自动生成流程 | 全做 |
| 搜索 | 模型供应商自带 web search + 用户给 URL 本地抓取正文 | 做 |
| C. 官方后端 | 登录、云项目、订阅、额度、支付、公告接口 | 不做 |
| D. 引导类 | 首启主题/语言引导、公告入口、How to Use、示例项目入口 | 占位 |

补充：

- 主题与语言的基础切换属于 A；“首启引导流程”属于 D。
- 搜索的配置：全局默认开关、单次对话覆盖、每次运行最大搜索次数、最大结果数；按供应商能力暴露。
- 搜索是显式能力：用户可关闭；查询与结果可见；不后台搜索、不自动建立索引。
- C 类不伪装成本地功能，不返回假数据；入口可以不存在，或明确说明不可用。

### 3.3 与 Explore 的边界

- 功能对齐，不做 1:1 视觉或代码克隆。
- 不使用 Explore 的代码、素材、字体、图标、文案、提示词、品牌。
- 不提供绕过 Explore 鉴权、付费或额度限制的能力。
- Explore 参考镜像只用于行为核对，不进入 Sporelink 发布物。

## 4. 层间边界

```text
React (TypeScript)  ── Tauri IPC ──  Rust
                                      ├─ domain
                                      ├─ store  ── VelesDB
                                      ├─ context
                                      ├─ LLM gateway ── 供应商 HTTPS
                                      └─ keychain
```

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| React | 渲染、输入、视图状态、调用 IPC | 直接 fetch、读文件、读 key、拼 SQL/VelesQL |
| Tauri IPC | command / event / channel，类型化契约 | 暴露任意命令执行、暴露 VelesDB 句柄 |
| Rust domain | 实体、不变量、用例 | 依赖 React 或 Tauri UI 类型 |
| Rust store | VelesDB 读写、reconcile、导入导出 | 把图边当事实来源、并发写 |
| Rust LLM | 供应商适配、流式、搜索工具、取消 | 把 key 返回前端、把原始 SSE 透传 |
| VelesDB | 持久化 point / edge / payload | 作为唯一事实来源之外的第二套业务存储 |

写入规则：

- 所有业务写操作经单一 `StoreWriter` 串行执行。
- payload 是事实来源；图边是派生索引，可在启动时重建。
- 每个实体有 `revision`；更新带 `expectedRevision`。
- 运行中的流式内容按检查点落盘；取消时保留已生成内容。

## 5. 迁移与验收

### 5.1 功能对照表

实现前先产出 `feature-parity.md`，逐项列出：

- Explore 入口/行为
- Sporelink 对应实现
- 验收方式（自动测试 / 手动脚本 / 截图）
- 状态（未开始 / 进行中 / 完成 / 不做）

没有对照表的条目，不进入实现。

### 5.2 数据

- v0.1 使用自有 schema；项目/全 Vault 可导出 JSON、可导入。
- 导出不含密钥。
- 不承诺读取任何归档实现的私有数据格式；如需要，单独写导入器，不在 v0.1 默认范围内。

### 5.3 跨平台

- Windows / macOS / Linux 至少完成构建与冒烟测试。
- 发布物包含第三方许可证与 VelesDB 归属链接。
- 不做自动更新检查。

### 5.4 性能

| 指标 | 目标 |
| --- | --- |
| 冷启动到可交互 | ≤ 2.5 s |
| 打开 1,000 cells 的项目 | ≤ 300 ms |
| 切换 cell | ≤ 100 ms |
| 流式首 token 展示 | 供应商返回后 ≤ 100 ms |
| 空闲内存 | ≤ 350 MB（10,000 条消息） |

### 5.5 安全

- WebView 不接触 API Key；key 只在 Rust 进程内使用。
- 供应商请求直连；没有 Sporelink 中转。
- 搜索可关闭；查询与结果可见。
- 日志脱敏；不记录消息正文、Authorization、API Key。
- 不引入遥测、崩溃上报、远程配置。

### 5.6 完成定义

- 功能对照表全部有结论。
- 关键路径有自动测试或可复现手动脚本。
- 错误路径有可行动文案。
- 文档与实现一致；契约变更先改文档。
- 跨平台构建通过。

## 6. 非目标

- 不做 Explore 之外的功能超集。
- 不做账号、云同步、协作、订阅、额度、支付。
- 不做移动端、Web 端、浏览器本地服务。
- 不做跨 cell 图结构、图搜索深度、自动知识图谱。
- 不写产品哲学、定位宣言、用户心智模型。
- 不把“AI 生成思维导图/总结/笔记”作为专门功能开发；Explore 已有入口按 B 类对齐，不新增自动流程。

## 7. 待拍板

1. **功能对照表的粒度**：按 Explore 入口逐项列，还是按页面/模块列。
2. **UI 对齐程度**：功能等价即可，还是要求布局、主题、卡片材质接近官方。
3. **D 类占位的具体含义**：保留入口但空内容，还是完全不出现。
4. **旧数据**：是否存在需要导入的 Sporelink 历史数据；若有，格式与优先级。
5. **VelesDB 许可证**：接受 source-available 依赖与“Powered by VelesDB”归属要求。
