# 手动冒烟脚本（v0.1.0-alpha）

> 目标：在不配置任何真实 API Key 的情况下，用 Mock 模型走通核心闭环。
> 测试用 `SPORELINK_CONFIG_DIR` 和 `SPORELINK_WORKSPACE` 指向临时目录；默认配置在 `~/.sporelink`，主数据在 `<workspace>/.spore`。

## 0. 启动

1. 启动 `npm run tauri dev` 或运行构建后的 exe。
2. 期望：窗口出现，首次显示引导弹窗；没有白屏或 Node/Key 泄露。

## 0.1 工作区

1. 打开设置 → 工作区；确认当前根路径与 `<root>/.spore` 正确显示。
2. 选择一个已有普通文件的文件夹（例如 `test_ws/`）；期望有 `.spore` 则打开，没有则创建。
3. 在文件管理器里确认 `.spore/workspace.json`、`.spore/db/` 出现；用户原文件没有被移动。
4. 导入工作区内的文档：文档 path 应保持工作区相对路径，`<root>/attachments` 不新增副本。
5. 导入工作区外的文档：期望复制到 `<root>/attachments/` 后再索引。
6. 文件列表/读取不应出现 `.spore` 或 `.sporelink`；直接读取 `.spore/workspace.json` 应被拒绝。
7. 切换另一个工作区再切回；项目/卡片应随工作区切换，原工作区数据不丢。


## 1. 首次引导

1. 选一个主题（如 Moss），观察背景/卡片即时变化。
2. 下一步选语言（简中 / 繁中 / 英），界面文案立即切换。
3. 模型步骤选 **Mock（离线）**，完成。
4. 欢迎页出现；点击 **How to Use**，示例项目打开。
5. 期望：示例项目有根卡片 + 深潜/发散/分支三张子卡；右侧 3D 树可拖拽旋转、滚轮缩放、点击切卡。

## 2. 发送与流式

1. 在根卡片输入“用一句话解释这个项目”，Ctrl+Enter 发送。
2. 期望：用户消息出现，Mock 流式输出；推理折叠块可展开；发送按钮变停止。
3. 点停止；期望保留已生成内容，状态为“已停止”。
4. 重新发送并等待完成；检查消息底部 token/耗时。
5. 点击助手消息的“重新生成”；期望新增一轮，旧轮保留。

## 3. 卡片树

1. 选中助手回答的一段文字 → 浮条选“深潜”；期望新子卡打开，上下文截止到该消息。
2. 回到根卡，选“发散”；期望新卡与根卡平行布局，带 `parallel_to` 关系。
3. 选“分支”；期望新卡从消息处分出，上下文截止到分支点。
4. 在 3D 树点击节点切卡；面包屑随之变化；Alt+方向键可切卡。

## 4. 上下文预览

1. 在输入区写一段草稿，点“上下文”。
2. 期望显示：system、路径消息、draft、知识/文档（如有）、token 预算、丢弃项。
3. 临时禁用一条路径消息，刷新后该项显示为排除。
4. 置顶一条消息；刷新后它进入 pinned 区。
5. 发送后，在消息/数据库层确认 `ContextSnapshot` 节点已生成（Settings → Performance 或导出 JSON）。

## 5. 搜索、收藏、回收站

1. Ctrl+K 打开命令面板；执行“搜索一切”。
2. 搜索“上下文”；期望命中卡片/消息/知识；点击跳转。
3. 收藏一条消息、一张卡片、一个项目；打开收藏视图，三组都出现。
4. 删除一轮对话；打开回收站，恢复该轮；回到卡片确认恢复。
5. 删除一张卡片（树模式）；回收站恢复；子树恢复。

## 6. 文档

1. 文档阅读 → 导入一个 Markdown/TXT/PDF。
2. 期望：TOC、分块正文、页码/标题；搜索框可过滤。
3. 选中/引用一个片段；回到当前卡片，草稿中出现引用块。
4. 存为知识；打开知识花园，条目带来源。
5. 从 URL 导入一个公开网页；期望正文被抽取为文档。

## 7. 知识

1. 新建知识条目，正文用自己的话解释一个概念。
2. 点“让模型检查理解”；Mock 返回反馈。
3. 在卡片上下文中加入该知识；预览显示 knowledge 项。
4. 生成项目摘要；期望新增 `summary` 知识条目。

## 8. 设置

1. 切换 9 套主题；取消后应回到原主题，保存后持久化。
2. 切换三种语言；日期格式随之变化。
3. 修改卡片宽度、密度、减少动效、2D 树；保存后生效。
4. 检查 Privacy：数据目录、数据库路径、网络目标列表可见；清除数据需要输入 `DELETE`。
5. 创建快照；修改项目；恢复快照；数据回到快照状态。
6. About 显示 GPL-3.0-or-later、Powered by VelesDB 链接。

## 9. 模型与 Key

1. 添加一个 OpenAI-compatible 模型；Base URL/模型/上下文窗口可编辑。
2. 输入一个假 Key 保存；期望只显示“已保存”，前端无任何读取 Key 的入口。
3. 导出全量 JSON，搜索假 Key 字符串；期望搜不到。
4. 删除 Key；状态变为“未设置”。
5. 不配置真实 Key；确认 Mock 仍可用，真实模型请求给出可行动错误。

## 10. 导出 / 导入 / 重启

1. 导出项目 JSON 和 Markdown；打开文件检查结构。
2. 导出全 Vault JSON；清空数据后导入；项目/卡片/消息/知识/文档引用完整。
3. 关闭应用再打开；数据完整，最后打开的项目/卡片可恢复（当前版本至少项目列表完整）。
4. 导入一个 ID 冲突的项目；期望重新分配 ID，旧项目不受影响。

## 11. 失败路径

1. 自定义一个不可达的 Base URL；请求应显示网络错误，不崩溃。
2. 删除正在使用的 Key；请求显示 `key_missing`。
3. 导入非法 JSON；错误文案可读，现有数据不破坏。
4. 导入不存在的文件；错误文案包含路径/原因。
5. 删除根卡片；期望被阻止或以子树方式处理，不产生孤立数据。

## 12. 安全检查

1. 前端 DevTools Network 不应出现供应商请求（请求只在 Rust）。
2. 日志中搜索消息正文、`Authorization`、`sk-`；期望没有。
3. 导出文件不包含 API Key。
4. 应用退出后 `Store` flush；重开数据在。
